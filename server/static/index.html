Backlog

Read-only — this board never writes to backlog/. Ask Claude in this project to add a task, move status, or record a decision; the board updates live. Columns sort P1 first. Priority: P1 urgent/blocking, P2 normal, P3 low/someday.

Manual

backlog-board keeps your dev work as plain Markdown files in backlog/ (epics, tasks, ADRs). Claude Code reads and writes them through the backlog skill; this board is a live, read-only view — edits go through files, and the board refreshes within about a second.

How to use it

  1. Ask Claude to add a task or epic (“add a task to fix the login bug”, “what’s next?”, “mark T-012 done”). The skill creates backlog/tasks/T-0xx-*.md and regenerates INDEX.md.
  2. Claude moves the task through its statuses while working; open this board to watch.
  3. When work reaches review, look at it and accept it by setting status: done and completed: YYYY-MM-DD.
  4. Record decisions as ADRs (“record a decision: …”); they show up in the ADR tab.

Statuses

StatusMeaning
investigateNeeds research or is stuck on something external.
todoPlanned, not started. inprogress is accepted as an alias and treated exactly like todo.
doingBeing worked on right now (tied to a Claude session).
reviewWork finished, waiting for a human to look at it.
doneAccepted. Epic status is derived from its tasks, never set by hand.

Commands

CommandWhat it does
/backlog-board:backlog-boardStarts (or reuses) the board server for this project and prints its URL. Safe to run repeatedly.
/backlog-board:backlog-handoffWrites a continuation task for in-flight doing work and prints the resume line, for stopping a session mid-task.
backlog skillTriggered by plain language: add a task/epic, “what’s next”, change status, record an ADR, check progress.
python3 backlog/build.pyRegenerates INDEX.md and validates the backlog (known statuses, duplicate ids). Run after any file change.
python3 backlog/build.py --new taskPrints a fresh random id: and created: for a new task (or epic). Claude uses this instead of picking IDs itself.
python3 backlog/build.py --archiveDeletes every done task/epic immediately (only git-tracked, clean files). Git history is the archive.
python3 <plugin>/server/serve.py --stopStops this project’s board server. Other flags: --port N, --dir NAME, --root PATH, --foreground.

Automatic behaviour

Runs when a Claude Code session starts, and again once per calendar day while the board stays up.

  • Board server starts at session start and stops at session end (when the last session for the project closes).
  • Review auto-accept: a review task untouched for review_after_days (default 1 working day, measured from updated:) becomes done with completed: stamped.
  • Old tasks removal: done tasks and epics older than archive_after_days (default 7 working days, from completed:) are deleted. Only git-tracked, clean files are removed, so everything is recoverable from git.
  • Auto-commit: the deletion is committed on its own as Backlog tasks update YYYY-MM-DD, touching only the deleted files.
  • Collision-proof IDs: new tasks get random IDs like T-k7f2m from build.py --new task, so several people or branches can add tasks without clashing. Order comes from created:. Older numeric IDs keep working.
  • INDEX.md: it is generated and gitignored, so branches never conflict on it; the session start rebuilds it after a pull or merge.
  • build.py sync: backlog/build.py is overwritten from the plugin at each session start — don’t hand-edit it.
  • Context nudge: while a task is doing and the context grows large, Claude is nudged to wrap up or hand off.
  • No task IDs in code: Claude is instructed not to write task/epic IDs into code or comments, since task files get deleted.

Recover a deleted task: git log --all --diff-filter=D --name-only -- 'backlog/tasks/T-051-*', then git show <sha>^:<path>.

Updating the plugin

  1. In Claude Code run /plugin marketplace update backlog-board, then /plugin update backlog-board. The /plugin menu works too.
  2. Restart the session so the hooks and the board server load the new version.
  3. On the next session start backlog/build.py is re-synced from the plugin automatically — nothing to copy by hand.
  4. If the board still looks old, run python3 <plugin>/server/serve.py --stop and start the board again.
  5. Upgrading from a version that committed INDEX.md? Run git rm --cached backlog/INDEX.md once and commit.
  6. Installed from a local clone? Bump version in .claude-plugin/plugin.json first — Claude keeps using its cached copy until the version changes.

Configuration

Optional file backlog/board.config.json (gitignored; commit it if the team should share it). Every key is optional.

KeyDefaultMeaning
port3201Board port. --port flag wins over this.
review_after_days1Working days before a silent review task auto-promotes to done.
review_auto_accepttruefalse makes review a human-only gate.
archive_after_days7Working days (weekends excluded) after completed: before a done item is deleted.
archive_enabledtruefalse turns off the automatic deletion.
auto_committruefalse deletes without committing.
nudge_at_tokens120000Context size where the wrap-up nudge starts.
nudge_every_tokens25000Growth needed before the nudge repeats.
require_deferral_linksfalsetrue: build.py refuses a done/review task with an unchecked subtask that doesn’t name a filed follow-up task.
{
  "port": 3201,
  "review_after_days": 1,
  "review_auto_accept": true,
  "archive_after_days": 7,
  "archive_enabled": true,
  "auto_commit": true,
  "nudge_at_tokens": 120000,
  "nudge_every_tokens": 25000,
  "require_deferral_links": false
}

To use a different folder than backlog/, put {"dir": "name"} in .backlogrc.json at the project root.
